# Frontend Handoff Reports

每个进入 PR 审查的前端任务必须在本目录新增 `<TASK-ID>.md`，并与页面、组件或 service 改动放入同一个 PR。

## 文件规则

- 文件名必须与总纲任务 ID 完全一致，例如 `FE-02.md`。
- 一个任务只维护一个交接报告；审查修改继续更新原文件。
- 报告必须注明依赖的后端任务、OpenAPI 版本和实际联调结果。
- 没有变化或风险时写“无”，不得删除栏目。
- 不得修改其他任务的交接报告。

## 模板

```markdown
# <TASK-ID> 交接报告

## 基本信息

- 任务 ID：
- 目标：
- 执行者：
- 分支：
- PR：
- 状态：IN_PROGRESS / REVIEW / DONE / BLOCKED

## 实现结果

- 已完成：
- 未完成：无

## 修改文件

| 文件 | 用途 |
| --- | --- |
| `path` | 说明 |

## 接口与配置变化

- 依赖后端任务：
- OpenAPI 版本：
- 新增或修改 service：
- app.json/env/constants 变化：无

## 页面规则

- 登录与权限：
- 加载/空态/错误态：
- 防重复操作与分页：

## 验证证据

| 开发者工具场景 | 结果 |
| --- | --- |
| 冷启动/页面进入/接口成功/接口失败 | PASS / FAIL / 未运行及原因 |

## 联调结果

- 后端环境：
- 成功路径：
- 失败路径：
- 尚未联调内容：无

## 风险与阻塞

- 已知风险：无
- 阻塞事项：无
- 需要负责人决定：无

## 下一任务输入

- 可复用组件或 service：
- 页面路由与数据结构：
- 接入注意事项：
```
